ArcFlare Desktop 0.6.1: fixes in Flow, 3D, Agent, Store and phone control, and the app's page no longer gets camera, microphone or notification access.

## Security

- The app no longer grants camera, microphone or notification access to its page. Only copying to the clipboard is allowed. Nothing in the app used the others.
- Studio setup only runs for a known model, and only borrows torch from a Python you picked.

## Fixes

- Flow: run from here no longer reuses old results after you edit an earlier node
- 3D: undo and redo keys keep the selection highlight hidden when you hid it
- 3D: Ctrl+S and Ctrl+F no longer switch the select tool or reframe the model
- Store: add all shows every added skill as added, and keeps a failure on screen
- Flow: stop now ends a rewrite node that is waiting on the chat model
- 3D: opening another mesh frees the last one's textures from GPU memory
- Agent: a message that fails to send goes back in the box instead of being lost
- Save as says why a copy failed in Jobs, Image and Speech instead of doing nothing
- Agent: stop says so when the session is already gone, instead of doing nothing
- Phone control keeps answering after one message fails before reaching the model
- Closing an agent folder while it starts no longer leaves its MCP servers running
- A ComfyUI workflow that saves no image now fails instead of waiting forever
- Studio setup only runs for a known model and only borrows torch from a Python you picked
- On macOS, update checks start again when you reopen the window after closing it
- Studio file lists still show when a file is deleted while they load
- The app no longer grants camera, microphone or notification access to its page

## The engine

The engine inside is the one from ArcFlare 1.4.0, which fixes crashes, hangs and unsafe paths in the agent, the hub and model downloads. Its notes list every change: https://github.com/Hakeperty/ArcFlare-Code/releases/tag/v1.4.0

## Not done, and not checked

- Nothing was tried by hand on macOS or Windows. The update-check fix for macOS has not been run there. The unit tests and the smoke test pass in CI.
- Edits made while a Flow run is going may still be overwritten when the run finishes, because its results are written back from the old settings. The review of the Flow fix reported this; we have not reproduced it. Edits made before you press run are covered.
- A future feature that needs the camera, microphone or notifications must be added to the permission list first, or it will be refused.

The app checks for updates when it starts and every 6 hours if that setting is on (Settings), or download the installer from arcflare.net/desktop.
