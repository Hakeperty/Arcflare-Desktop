ArcFlare Desktop 0.6.2: phone control, Agent, Store, 3D and window fixes, and harnesses that open from paths with & or ( ).

## Fixes

- Stopping a flow while a job is still starting now cancels that job
- The panda on Home no longer asks you to pick a model while a download runs
- A folder you open in Agent is no longer replaced by the last one reopening late
- Agent no longer misses progress sent while its screen was opening
- The title bar no longer shows "no model" for a while right after a model loads
- The phone button no longer shows an older remote-control status at startup
- The update pill no longer shows an older update status at startup
- Refreshing the Store no longer undoes a skill or server you just added
- Opening two 3D meshes quickly now shows the one you opened last
- Phone control: pressing start twice or stop during start no longer leaves it on
- Choosing several models quickly loads them one after another, not two at once
- On macOS, closing the window no longer turns off phone control or stops studio jobs
- On Windows, harnesses open even when the app is installed under a path with & or ( )
- The app stays responsive while it lists many saved agent sessions
- The first-run screen no longer freezes the app while it looks up your graphics card
- Phone control: start, stop, then start again quickly now leaves it on
- Free graphics memory in the app no longer jumps back to an older reading
- Store refresh works even while an add or remove is still running
- Opening two 3D meshes quickly no longer shows an error for the one you left
- Agent keeps your saved tool switches when you pick a folder right away
- Agent: switches you change at once are not undone by the saved ones, and opening a folder never waits forever

## The engine

The engine inside is the one from ArcFlare's main branch at build time, which includes ArcFlare 1.4.1 (https://github.com/Hakeperty/ArcFlare-Code/releases/tag/v1.4.1) and its call and question fixes for the phone page.

## Not done, and not checked

- Nothing was tried by hand on macOS or Windows. The macOS window-close change and the Windows harness quoting have not been run on those systems. The unit tests and the smoke test pass in CI.
- Phone control and Agent session fixes are covered by unit tests only where the code can be loaded without a window; the screens have no component tests.
- The Windows updater has no publisher check, because the installers are not code-signed.

The app checks for updates when it starts and every 6 hours if that setting is on (Settings), or download the installer from arcflare.net/desktop.
